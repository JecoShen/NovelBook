# novel-workflow-07-opening-plot-design：开局剧情设计

用于把新书的定位、世界书和当前 World Engine 状态转成开篇可写的剧情。默认关注前三章附近的阅读体验，但章节数量由节奏决定。

默认按用户主导推进：先了解用户想要的开局画面、第一股压力、主角第一个选择和不想采用的套路。可以给 2 到 4 个开局推进方向作为灵感，让用户选择或修正；只有用户明确要求“你来设计”“直接给完整开局方案”时，才由 Agent 主导拆完整开局。

开局设计使用 `novel-workflow-08-plot-planning` 的 Phase 1-3 做通用剧情讨论：Phase 1 判断本轮意图（自由探索/宏观设计/当前片段推进/落库），Phase 2 读取当前世界状态，Phase 3 判断 LOD 粒度。开局特有的结构性问题由本 skill 负责，通用分析方法委托给 08。

本 skill 与 08 的分工：

| 本 skill（07）负责 | 08 负责 |
| --- | --- |
| 开局承诺：读者前三章会看到什么 | 上帝视角分析、主角代入、多角色代入 |
| 第一个异常、第一股压力、第一个主动选择 | 随机扰动素材池 |
| 开局章节段落拆分与钩子设计 | World Engine 状态推导与写入 |
| 商业网文节奏套用 | LOD 粒度判断与 subject 管理 |
| 开局自检（压力、能动性、钩子） | 剧情事实确认与 canon 落库 |

开局讨论时，leader 先在 07 框架下锁定开局承诺和段落结构，需要做通用分析（上帝视角、角色代入、随机素材）时切到 08 的 Phase 1-3；确认剧情事实后，用 08 的 Phase 4-8 写入 World Engine。

角色代入可以采用旁白式协作：用户扮演主角或指定角色，Agent 描述环境、压力、可见线索、其他角色反应和可选行动；不要替用户控制角色的关键选择。用户选择后，再推演直接后果，并询问是否纳入正式剧情。

## 是否需要 World Engine

在进入正式开局设计前，先判断当前项目是否需要 World Engine 来追踪动态状态。

**需要 World Engine 的典型场景**（满足任一条即建议初始化）：

- 开局涉及多个角色的位置、状态或认知变化。
- 有势力行动、物品转移、倒计时或隐藏状态需要追踪。
- 角色有 HP/MP、技能成长、关系变化等需要随剧情更新的属性。
- 用户明确表示"我要正经写这个故事了"。

**不需要 World Engine 的典型场景**：

- 单视角、线性叙事，所有状态可以从 lorebook 静态设定推导。
- 开局只有一个场景、少量角色、无复杂状态交互。
- 用户还在探索开局方向，连前三章结构都没定。
- 纯灵感讨论或实验性写作。

如果需要 World Engine 但尚未初始化，先进入 `novel-workflow-world-engine-init`。如果不需要，可以基于 lorebook 静态设定直接讨论开局——但后续推进到正式写章节时可能仍需补初始化。

## 前置要求

开始前应尽量具备：

- 小说简介、类型基调和核心 hook。
- 主角基础定位。
- 最小世界书条目。
- 开局相关的角色、地点或势力设定（来自 lorebook 或 World Engine）。

如果世界书基础缺失，先进入 `novel-workflow-03-lorebook-bootstrap`。World Engine 是否需要，见上方「是否需要 World Engine」判断——不是所有开局都必须先初始化 World Engine。

## 通用分析方法（委托 08）

开局讨论中需要的上帝视角分析、主角代入、多角色代入、随机扰动素材等通用方法，全部委托给 `novel-workflow-08-plot-planning` 的 Phase 1-3。不要在 07 内重复这些方法的具体步骤。

本 skill 聚焦开局特有的结构性问题：

## 开局设计能力

### 锁定开局承诺

先询问或整理读者在开篇会看到什么：

- 主角第一眼处境。
- 第一股压力。
- 第一个主动选择。
- 第一轮爽点或情绪释放。
- 章末继续阅读的理由。

如果用户还没有明确方向，先给几个互斥开局候选，说明它们分别会带来怎样的阅读期待。

### 上帝视角分析（委托 08）

开局节奏、爽点、悬念、压迫感等通用分析切到 `novel-workflow-08-plot-planning` Phase 1-3。这里只做开局特有的承诺检查：读者前三章得到什么承诺、第一个异常是否足够抓人。分析后给 2 到 4 个开局方向，让用户选择、混合或否定。

### 角色代入（委托 08）

主角代入、多角色代入、旁白式推演等切到 `novel-workflow-08-plot-planning` Phase 1-3 的分析方法。开局特有的角色检查只做一项：主角的第一个主动选择是否成立。

### World Engine 状态推导

需要从设定自然推出开局时，参考 `novel-workflow-08-plot-planning` 的状态推进流程：先用 `execute_world` 查询角色、地点、势力和最近时间线，再从环境、资源、势力行动、仪式异常、角色误判或随机变量推出多条候选因果链。推导结果只是候选剧情压力，用户确认后才整理成正式开局，并按 LOD 粒度写入 World Engine。

### 随机扰动素材（委托 08）

开局太顺或太线性时，切到 `novel-workflow-08-plot-planning` 获取随机素材池。

### 套用商业网文节奏

偏商业网文或用户明确要爽点时，读取并使用 `novel-technique-commercial-rhythm`。它是在剧情设计基础上的节奏补充，不替代本 skill 的开局判断：

- 先用它的前置模板安排危机、反抗、升级、低谷、释放、奖励和钩子。
- 草案完成后再用它的后置校验检查主角能动性、压力、释放和奖励。

不要把 `novel-technique-commercial-rhythm` 理解成固定题材，它只是节奏框架。

### 整理开局段落

用户确认开局方向后，再按节奏自然拆成 2 到 5 个开局段落或章节草案，不强行三章。

每段至少说明：

- 本段发生什么。
- 本段的读者期待是什么。
- 主角做了什么选择。
- 本段结尾留下什么钩子。

### 落到 World Engine

需要落库且方向已经确认时，进入 `novel-workflow-08-plot-planning` 的 Phase 4-8，把确认后的开局事实写进 World Engine：

- 用项目日历字符串确定开局时间。
- 按 LOD 判断哪些角色、地点、势力需要 subject。
- 写入关键位置、状态、认知、关系和势力动向。
- 不把未确认的候选剧情写入时间线。

引用优先指向已有 lorebook 和 World Engine subject，不要把动态剧情事实倒灌成稳定世界设定。

## 自检

- 开篇是否迅速给出压力或异常？
- 主角是否有主动选择，而不是只被带着走？
- 每段是否都有读者期待和推进功能？
- 低谷与释放是否有铺垫？
- 结尾是否留下下一步问题、目标或威胁？
- 是否已经用上帝视角、主角代入和至少一个非主角视角检查过开局。
- 采用的随机扰动是否经过用户确认，并能改变压力、误判或行动选择。

## 完成标准

- 开局范围明确，且不被“三章”机械限制。
- 开篇压力、主角行动、低谷、释放和钩子成立。
- 开局方向由用户确认，不是 Agent 单方面定稿。
- 已通过多视角切换检查主角行动和其他角色反应。
- 需要落库时，开局事实已能按 `08` 的流程推进进 World Engine。
- 后续可以进入 `novel-workflow-09-chapter-writing` 或更长线 `novel-workflow-08-plot-planning`。
